# Deployment

Nothing is deployed yet. These steps prepare a hosted demo on Neon, Render and Netlify or Vercel.

## 1. Database: Neon

1. Create a Neon project and copy the connection string.
2. From your machine:
   ```bash
   cd backend
   export DATABASE_URL='postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require'
   alembic upgrade head            # creates the schema
   python -m app.seed              # optional: synthetic demo data. Demo databases only
   ```
   `python -m app.seed --reset` drops every table first. Never run it against real data.

## 2. API: Render

1. New Blueprint, point it at this repository. `render.yaml` defines the service.
2. Set `DATABASE_URL` (Neon), `FRONTEND_URL` and `CORS_ORIGINS` (your frontend address).
   `SECRET_KEY` is generated by Render.
3. Migrations run before each deploy (`alembic upgrade head`).
4. Check `https://<api>/api/health`.

## 3. Website: Netlify or Vercel

Netlify: base directory `frontend`. `frontend/netlify.toml` sets the build. Add the
`@netlify/plugin-nextjs` plugin if Netlify does not add it for you.
Vercel: import the repository and set the root directory to `frontend`.

Environment variables for either host:

| Variable | Value |
| --- | --- |
| BACKEND_URL | Your Render API address, no trailing slash |
| NEXT_PUBLIC_POSTHOG_KEY | Optional |
| NEXT_PUBLIC_POSTHOG_HOST | Optional, for example https://eu.i.posthog.com |

The website forwards `/api/*` to the API, so the browser uses one origin and the session cookie stays
first-party.

## 4. After deploying

- Sign in with a demo account and run through docs/DEMO.md.
- Run the ledger integrity verification.
- Confirm `/api/health` reports `TEST MODE`.

## Security settings to finish after the first deploy

1. **Proxy hops.** Rate limits need the visitor's real address. Sign in once on the live site, then open the
   audit log as the platform administrator and look at the address recorded for `user.login`. If every
   visitor shows the same address, raise `TRUSTED_PROXY_HOPS` by one and redeploy. If the address looks
   like one a visitor could invent, lower it.
2. **Least-privilege database role.** Run `docs/sql/app_role.sql` in the Neon SQL editor, then point
   `DATABASE_URL` on Render at the `scp_app` role. Keep the owner role for migrations only.
3. **Spending limits.** Stay on the free plans with no card on file where the host allows it. Where a card
   is required, set a billing alert or a hard limit on Neon, Render, Netlify or Vercel, and PostHog.
4. **Demo accounts.** `python -m app.seed` refuses to run with `ENVIRONMENT=production` unless
   `ALLOW_DEMO_SEED=true`. Use it only for a public demo that holds synthetic data.

## Production notes

- `ENVIRONMENT=production` stops the app creating tables on start. Alembic owns the schema.
- Set `COOKIE_SECURE=true`.
- Free Render services sleep when idle. The first request after a pause takes longer.
- Rate limiting is per process. Use a shared store before running more than one instance.
